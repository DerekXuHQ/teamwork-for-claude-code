# Teamwork for Claude Code

[English](README.md) · [中文](README.zh.md)

**在 claude.ai 上带一支 Claude 小队：一个 lead 统筹，几个线程分头干活，你提的每件事都记在台账上，直到你说结束。**

**用过了？[填一份实地报告](https://github.com/DerekXuHQ/teamwork-for-claude-code/issues/new?template=field-report.yml)**，说说哪些好用、哪些不好用。

一个会话当 **lead**，负责拆活、开**线程**（其他会话），把新需求交给原本就管这一块的线程，最后把成果合到一起。每个项目的看板、说明和记忆都放在 `.teamwork/` 目录里，新会话从这本台账接着干，不靠上一个会话的记忆。

这是社区做的 skill，不是 Anthropic 官方产品。想用 [Claude Code Projects beta](https://code.claude.com/docs/en/claude-projects.md) 那套协作方式、但还没拿到资格，或者需要线程直接在自己电脑的文件夹里干活，都可以用它。

## 30 秒上手

先准备好：线程要用哪台电脑上的文件夹，就在那台电脑上开着 Claude Code 的 Remote Control，登录的账号和 claude.ai 上用的是同一个。然后在这个 Remote Control 环境里开一个会话，让它跑下面三条命令。`<served folder>` 换成 Remote Control 服务的文件夹，`<project>` 换成里面的项目文件夹。

**1. 下载 skill**

```bash
git clone https://github.com/DerekXuHQ/teamwork-for-claude-code <served folder>/teamwork-for-claude-code
```

**2. 先预演一遍，看安装会改哪些地方（只预演，不写入任何文件）**

```bash
python3 <served folder>/teamwork-for-claude-code/scripts/install.py --link --project <served folder>/<project> --served <served folder>
```

**3. 正式安装**

```bash
python3 <served folder>/teamwork-for-claude-code/scripts/install.py --link --project <served folder>/<project> --served <served folder> --apply
```

装好后，在同一个环境里**新开**一个会话（skill 只在会话启动时加载），输入：

```
/teamwork new <project>
```

lead 会先问目标，再列出建议的线程和任务，等你点头才开工。

**先确认配置目录。** 安装脚本往 `$CLAUDE_CONFIG_DIR` 里写；没设这个变量，就写 `~/.claude`。`--help` 和每次预演都会打印它找到的是哪一个。如果你的 Remote Control 服务用的是别的目录（比如 `CLAUDE_CONFIG_DIR=~/.claude-work`），加上 `--config-dir ~/.claude-work`，不然会找不到 `/teamwork`。

## 功能

现在已经有的，按你作为用户能看到的效果列出。

<!-- features:start -->
### 开场 <!-- group:A -->
- **先报家门。** lead 第一句话就说自己是哪个项目的 lead、权限托管成没成；中途接手的 lead 还会讲清接了什么、各线程当时在做什么。 <!-- f:A1 A6 -->
- **先提方案，问题一次问完。** lead 按你的目标提一套起步线程；只有你能答的问题列成一张单子，每题附建议，回一句「按建议」就行。 <!-- f:A3 A4 -->
- **不偷偷打折扣。** 权限、模型、范围、恢复步骤，哪样没按原计划来，当场告诉你，并给出几条路。 <!-- f:A7 -->

### 你能看到什么 <!-- group:B -->
- **第一次建好先带你看一圈。** 台账里记了你几件事、看板上有什么、去哪儿看，lead 主动说。 <!-- f:B2 -->
- **你说一件事，lead 回一句回执。** 回执里有台账编号和交给了哪个线程；之后派出、接单、评审、合并，每走一步都告诉你。 <!-- f:B3 B4 -->
- **等合并的、撞车的，看板上都有。** 几个成果在等合并、评审结论是什么；哪两条线程要改同一块、谁在等谁。 <!-- f:B8 B13 -->
- **是哪种交付、哪一版，开头就写明。** 回复第一行写清这是对照分析、新方案还是素材；进度里只给最新一版的链接，旧版标「别用」。 <!-- f:B9 B10 -->
- **全队共用一张问题清单。** 同一个问题只报一次，修好了全队都知道。 <!-- f:B12 -->

### 需求与功能 <!-- group:C -->
- **两头都对得上。** 你的每件事都能落到某个功能或任务，每个功能都能追回你的原话；任务里同时留着你的原话和 lead 的整理。 <!-- f:C2 C7 -->
- **每轮收尾自查四件事。** 听到了没记、记了没派、派了没回、回了没报。赶工时的新要求、lead 提了还在等你回的事，也一样记在台账上。 <!-- f:C5 C9 C10 -->
- **例子不是命令。** 你举的例子、打的比方、随口一句评论，不会被当成任务派出去；记偏好时连边界一起记，不会用过头。 <!-- f:C8 C11 -->
- **升级不丢老台账。** 老记录会分进新的状态，先给你看预览，你点头才改。 <!-- f:C12 -->
- **反复出问题就查根。** 同一块第二次坏了或被你纠正，lead 不再单点补：列全症状、找共同原因，问你一次是根治还是先打补丁。
- **派活先看手头有什么。** 每个任务都列出这件事已有的材料，线程接单时说明用了哪些。

### 权限、模型与额度 <!-- group:D -->
- **GPT 用不了会说明白。** 告诉你原因、大概什么时候恢复，并附一个默认做法：你没回就按它办。 <!-- f:D2 -->
- **权限和席位按你选的档位走。** lead 开出的会话沿用你选的权限档位。选「随意开」，lead 按主题开线程不再问；选「先问我」，开之前先问。 <!-- f:D3 D4 -->
- **点过头的照办，被拦下的交给你。** 你已经同意的对外动作，lead 替你去做；被平台安全检查拦下的那一步交回给你，不绕过去。 <!-- f:D6 -->
- **交给 GPT 的活有规矩。** 比如不许改测试去迎合实现；结果由 Claude 复核，私有的东西不外传。 <!-- f:D7 D8 -->
- **额度有人盯，模型有建议。** lead 大约每小时查一次额度，快到线时建议新活交给哪个模型。哪个模型做不好就升一级，汇报里会说；线程不用换座位，把活分给别的模型的子 agent 就行。 <!-- f:D10 D12 D13 D14 -->

### 盯线程 <!-- group:E -->
- **会话目录。** lead 的对话里列出所有会话：lead 排第一，分组排列，点链接就能进去。 <!-- f:E1 -->
- **要点几下，提前说。** 一次开一批线程之前，lead 先告诉你可能要确认几次；托管生效后还有哪些情况会来问你，也说一遍。 <!-- f:E6 E11 -->
- **线程卡住认得出来。** 比如卡在清理临时文件上，或者停在批准框前。 <!-- f:E8 -->
- **线程都是独立会话。** lead 给每个线程单开一个会话；已知的那种把线程嵌在 lead 里开的做法会被拒绝。
- **巡检顺带看磁盘和机器。** 报告磁盘空间和机器状况，能放心清的自动清，其余列给你定。

### 决定与默认 <!-- group:F -->
- **长期要求跟着任务走。** 你定下的长期要求写进派活模板，每次派活自动带上；线程也按同一条短规矩办：把事想全，不出圈。 <!-- f:F4 F9 -->
- **默认做的、答应过的，都查得到。** 替你按默认做的决定记在台账上，事后能查、能改。答应你的事要么做完并附证据，要么写明状态：等你定、不做（附理由）、已落地（附证据）。 <!-- f:F5 F6 F7 -->

### 交付物 <!-- group:G -->
- **交付物是能点开的链接。** 开头写清是草稿还是定稿、还差什么。 <!-- f:G1 -->
- **换新 lead 不断档。** lead 跑久了会建议换一个新会话，台账、看板、功能清单原样接上。 <!-- f:G3 -->
- **到你手上之前先过一遍。** 第三方评审交给没参与过的会话或模型；往外发的东西先给你过目；安装包、录制版，lead 先核对说好的内容都在，再说「能用了」。 <!-- f:G4 G5 -->
- **能撤回的一步不干等。** 方向你已经选定、又撤得回来的事，赶时间时直接做，并记成「按默认做」。 <!-- f:G7 -->
- **先验主结果。** 任务写明你最后会看到什么，先在真东西上验这个结果，再看细节。

### 汇报干净 <!-- group:I -->
- **汇报里没有技术流水。** 提交号、命令输出不出现在给你的汇报里，证据收在链接后面；看板上已结束的线程和空席位收进折叠区。 <!-- f:I2 I3 -->

### 席位与交接 <!-- group:J -->
- **定过的事不再问。** 提问前先查代码、当前文档和决定记录。 <!-- f:J1 -->
- **归档前先交接。** 没发出的消息、没合的成果、悬着的问题，先记进台账；交接材料里单写一段「环境和做法变了什么」。 <!-- f:J2 J6 -->
- **每个会话都带着规矩和名单。** 完整的规矩和当前成员名单都在线程自己的会话里，恢复或重开的也一样；名单上没有的会话，先问 lead 再发消息。 <!-- f:J3 J8 -->
- **在线程里说的话也会记账。** 你偶尔直接跟某个线程说的事，线程答完会转告 lead 记进台账。 <!-- f:J5 -->
- **换座一句话。** 换线程说「把 X 换掉」，换 lead 说「交给继任」。 <!-- f:J9 J14 -->
- **新会话先核对再上岗。** 先做一次体检，再自己做新旧对比：任务、分支、提交、你的规则和要求逐条对。 <!-- f:J10 J12 -->
- **换 lead 有确认，也有退路。** 每个线程确认认了新 lead，定时提醒转到新 lead 名下。换到一半出问题：换一个候选，或者补交接重测；还不行就取消，原来的照旧。 <!-- f:J15 J16 -->

### 会话体检 <!-- group:L -->
- **开局先查环境。** 每个新会话（lead、线程、继任）花几秒钟检查环境，比如自动模式有没有生效。 <!-- f:L1 -->
- **开局体检，自动出题打分。** 几道题在会话外面出、在外面打分，成绩记上看板。目前不过的只告诉你，不自动关也不自动换；考完把测试内容作废，再接着做你的正事。 <!-- f:L2 L3 L4 -->
- **交接测验。** 接手、换届、接力时，先单独测一遍会话本身，读完交接包再答题。 <!-- f:L5 -->
- **压缩后自查。** 上下文被压缩后，会话重读规矩、自查一遍，任务简报卡也会重新放到它面前。

## 安装、升级与回滚

安装脚本不删任何东西：新规则合并进已有设置，改设置文件之前先留一份 `.bak` 备份。它把 skill 链到你的配置目录（加了 `--link`，以后 `git pull` 就是升级），加一组权限规则让线程汇报时不卡在确认框上，再加一个会话启动 hook，让这些文件夹里的会话一开始就看到看板。全部选项见 `python3 scripts/install.py --help`，其中有推送前拦私有词的开关。

用 `--link` 装的话，检出分支上合进去的改动，新开的会话马上就用上。想自己决定什么时候生效，就用发布快照：先跑 `python3 scripts/release.py status`，再用 `publish`、`rollback` 或 `edge`（不加 `--apply` 都只是预演）。每条规则和命令的细节见 [`references/setup.md`](references/setup.md)（英文）。

## 和 Projects beta 比一比

| | Claude Code Projects beta | Teamwork |
|---|---|---|
| 谁来统筹 | 项目对话 | 跑着 `/teamwork` 的 lead 会话 |
| 一个线程管什么 | 一个任务 | 一块固定的职责范围；后续需求还交给它，前面的来龙去脉都在 |
| 线程在哪儿跑 | 默认在云端，也可以经 Remote Control 跑在本地 | 每个线程自己选：Remote Control 跑在你的文件夹里（各用各的 git worktree），或者跑在云端 |
| 线程之间能不能对话 | 文档没写 | 每个线程都有花名册；不归自己管的活转给对应线程，同时抄送 lead |
| 开工前有没有计划 | 建议开哪些线程 | 一张任务表：谁负责、依赖什么、做到什么程度算完，你批准后才开工 |
| 记忆 | 云端线程读 `MEMORY.md` | `.teamwork/MEMORY.md` 发给每个线程，Remote Control 线程也有 |
| 断了怎么接上 | 靠最近的消息和记忆 | 靠磁盘上的台账，会话启动时和上下文压缩后自动重新注入 |
| 界面 | 侧边栏总览 | 一个看板文件加 lead 的状态回复，没有侧边栏 |
| 隔离 | 项目线程不出现在普通会话列表里 | 靠约定：文件夹、`[project] thread · focus` 格式的标题、标签 |
| 谁能用 | 拿到 beta 资格的人 | 有 Claude Code 和 Remote Control 就能用 |

逐项对比见 [`references/projects-parity.md`](references/projects-parity.md)（英文）。

## 工作原理

```
claude.ai（网页 / App）
   │  你可以直接和任何一个会话说话
   ▼
lead  ── Remote Control 会话，运行 /teamwork，管一个项目的 .teamwork/
   │  create_session / send_message / get_session / list_events / interrupt_session
   ├── rc 线程 "ui"        ── 项目文件夹里的 Remote Control 会话（有自己的 git worktree）
   ├── rc 线程 "api"       ── 项目文件夹里的 Remote Control 会话
   └── 云端线程 "research" ── 云端会话，通过对话记录和 git 汇报
```

看板是 `.teamwork/BOARD.md`，每次有变动都重新生成。每条消息第一行是固定格式的消息头，比如 `[tw:shop] TASK lead -> ui T3`；线程每一轮结束都附一个固定的状态块。

**完整机制**写在 [`docs/framework-zh.md`](docs/framework-zh.md)（[English](docs/framework.md)）：角色、台账、消息协议、状态机、路由、同意边界、故障恢复，以及换一个宿主平台要具备什么才能跑起这套框架。建议先读开头的「5 分钟概览」。

哪种会话能给哪种会话发消息，是在真实账号上逐一试过的：Remote Control 会话之间可以互发；lead 能创建云端线程、给它们发消息，但要读它们的对话记录才知道结果。细节和还没证实的部分见 [`references/transport.md`](references/transport.md)（英文）。

## 命令

| | |
|---|---|
| `/teamwork new <name>` | 新建项目，定目标和说明 |
| `/teamwork use <name>` | 让当前会话接手一个已有项目，当它的 lead |
| `/teamwork projects` | 总览所有项目：各自的 lead，有什么在等你 |
| `/teamwork plan` | 列出建议的线程和任务，等你点头 |
| `/teamwork go` | 开始已批准的工作 |
| `/teamwork status` | 挨个查一遍线程，汇总汇报 |
| `/teamwork route <request>` | 把一个需求交给负责它的线程 |
| `/teamwork recall <thread>` | 叫停一个线程，把它手上的活收回来 |
| `/teamwork close` | 收尾，结束项目 |

也可以直接跟 lead 说话：「这个交给 UI 线程」「所有线程什么进度」「最多同时跑两个」。lead 还会在汇报前先核对成果，需要时把自己交接给新会话，推送前挡住不该公开的内容；完整做法见 [`SKILL.md`](SKILL.md)。

## 需要什么

- 带 Remote Control 的 Claude Code，登录的账号和 claude.ai 上的一致。
- 线程要用哪台电脑的文件夹，那台电脑上就得开着 Remote Control 服务。其余操作都在 claude.ai 上完成。
- 那台电脑上装有 Python 3 和 git。
- 云端线程要改代码的话：一个你的账号能访问的 GitHub 仓库。

## 限制

- 一个 Remote Control 服务默认最多挂 32 个会话，上面所有项目和 lead 共用，云端线程不算在内。除此之外线程数量不设上限，但套餐的用量限制照样算，每个线程都是一个完整的会话。
- 没有侧边栏，看板就是一个文件，再加上 lead 的状态回复。
- 隔离靠约定（文件夹、标题、标签），平台本身不强制。线程会出现在你平时的会话列表里。
- 云端线程的状态是 lead 去拉的，不是它们推过来的，所以状态只更新到 lead 上一次巡检的时候。
- 还没亲手测过：你在某个线程里自己敲 `/clear` 以后的情况（lead 没法远程替线程清空上下文）。
