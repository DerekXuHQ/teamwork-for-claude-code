## Observations

1. **`list_events` with `kinds` and a small `limit` looks empty.** The filter runs after the page is read,
   so `limit: 3` on a busy session returns no `data` at all, only `has_more: true`. Use `limit: 100`
   and page backwards with `before_id` until a `result` is found. A reader that trusts the first page
   will think the thread never reported.
2. **A thread mid-first-turn has no `result` event.** Its only live signal is `get_session.task_summary`
   (core: "setting up worktree for install.py copy-skip task"). A sweep should fall back to it.
3. **Messages queue into a running turn.** Core ACKed within its running T2 turn, ~1 min after the send,
   so rc→rc delivery does not wait for turn end here.
4. **Worktree creation is not done by the lead.** The thread brief points to a worktree path, but for
   field it did not exist. Either the lead creates it in `tw.py` start, or the brief should say
   "create it if missing" with the exact command.
5. **Header task id drift.** Core's ACK used `P2` as the task id; there is no task P2 on the board
   (the probe id leaked into the header). Harmless here, but a parser keyed on task ids would miss it.
6. **Interrupt shows up as a user interrupt.** In the recalled thread the interrupt reads
   `[Request interrupted by user]`, the same text as a real user stop. The thread can only tell it
   was the lead from the RECALL that follows, so the RECALL must come right after the interrupt.
7. **Header task id drift, again.** Core's copy to the lead used `P2,T7`: a probe id plus a task id
   that is not on field's board. Header task ids should be limited to ids on the board, or `-`.
8. **Interrupt order matters (L3).** Because `interrupt_session` cancels queued messages, a RECALL
   sent before the interrupt is lost. Handed off to core: document the order and make the RECALL's
   first sentence "The lead just interrupted you."
9. **Cloud → rc handoffs cost one sweep interval (L6b).** It works, but at ~10 min it is the slowest
   path in the team. Cloud threads should put the handoff in `handed_off` early in the turn's
   STATUS, and the lead's sweep interval sets the upper bound.
10. **Rc threads and cloud threads run in different permission modes.** Cloud threads default to
    `auto` (L6a); rc threads inherit Remote Control's default and prompt on every call (L5, I1).
