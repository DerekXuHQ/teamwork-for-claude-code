# Prior art and ideas to adopt

Survey of comparable open-source projects, November 2026. Star counts as shown on GitHub pages at the time; last-update dates were not verifiable.

## Finding

No other project found runs the coordinator from claude.ai and drives Remote Control and cloud sessions through the
`claude-code-remote` tools. Almost everything else is local-first: workers in tmux panes and git worktrees on one
machine, state in SQLite or files, a terminal UI.

The closest pieces:

- [cc-tap](https://github.com/es617/cc-tap): an MCP server over the Remote Control API (list, read, send, send-and-wait). It cannot create sessions and has no coordinator, protocol or board.
- [Cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging) (official): plain `SendMessage`, one-way to cloud sessions, `notify_when_idle` only on the same machine.
- [Agent Teams](https://code.claude.com/docs/en/agent-teams) (official, experimental): lead + named teammates, shared task list with dependencies, mailboxes, `TeammateIdle`/`TaskCompleted` hooks. Local only, one team per session.

## Comparable projects

| Project | Shape | Worth borrowing |
|---|---|---|
| [Gas Town](https://github.com/steveyegge/gastown) (~18.8k★) | "Mayor" coordinator, persistent worker identities with short-lived sessions, git-backed issues ("Beads"), patrol agents for stuck work, Bors-style merge queue | Identity that outlives the session; a merge queue; asking a predecessor's transcript ("seance") |
| [OpenRig](https://github.com/mvschwarz/openrig) (~8.9k★) | Teams in YAML, stable seat addresses, broadcast/chatroom, snapshot and restore | Seats whose session can be swapped; `CULTURE.md`; hold automated messages while the human types |
| [maniple](https://github.com/Martian-Engineering/claude-team) (48★) | Manager controls workers through an MCP server | Message-and-wait with any/all; 20-minute stuck threshold; adopting existing sessions |
| [claude-coordinator](https://github.com/JDonaghy/claude-coordinator) | Headless workers per machine, SQLite rebuildable from GitHub issue comments, Work→Test→Review→Merge gates | Zero-context reviewer per change; acceptance tests written first; declared files checked against real diffs |
| [multiclaude](https://github.com/dlorenc/multiclaude) (565★) | Supervisor, one task = one branch = one PR, merge queue on green CI | CI as the only thing that makes progress permanent |

| [claude-peers-mcp](https://github.com/louislva/claude-peers-mcp) (~2.2k★) | Local broker, `set_summary` per session | Each thread publishes its own one-line summary |

## Ideas to adopt, ranked

1. **Stuck detection.** Flag a thread on the board when it has produced no `<tw-status>` block for N minutes while `working`; the lead nudges it with a FOLLOWUP or tells the user.
2. **Independent review gate.** A fresh reviewer thread with no prior context checks each change before merge; add an explicit review step and, for code, "CI green" as the merge condition.
3. **File leases.** Each task declares the paths it will touch (`conflicts_with`); the lead checks them against other in-flight branches' real diffs before dispatching, and rejects overlapping work.
4. **Seats that outlive sessions.** A thread name is a seat; on RECALL or a dead session, a new session takes the seat with a handoff built from the old transcript.
5. **Rebuildable ledger.** Reconstruct `.teamwork/state.json` from session transcripts and tagged commits if it is lost.
